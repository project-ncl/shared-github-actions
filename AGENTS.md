# AGENTS.md

This repository contains **no application code**. It is a library of reusable
GitHub Actions — composite actions and `workflow_call` reusable workflows — that
ProjectNCL (PNC) repositories consume via `uses:`. "Building" here means editing
and validating YAML; there is nothing to compile or run locally.

## Commands

Run these before declaring any change done. Report the commands, their output,
and anything that could not be run:

```sh
actionlint
zizmor .github/
```

CI runs both via `validate-gh-action.yml` (triggered on PRs by `private-validate.yml`).
If either tool is not installed locally, say so rather than skipping.

## Before changing

- Read the target workflow/action file and its `README.md` section before editing.
- Verify action versions and input names from the actual files — do not guess.
- Ask before changing a workflow's inputs, secrets, or permissions: callers depend on them.
- Stay in scope; do not refactor surrounding code unrelated to the task.

## Layout (non-obvious points)

- `private-*.yml` workflows are **this repo's own** plumbing and must not be copied by callers.
- `.github/dependabot.yml` and `.github/release.yml` are sample files intended to be copied into PNC repos (ecosystems are commented out and must be uncommented per repo).
- `README.md` is the caller contract — keep it in sync when inputs, secrets, permissions, or behavior change. Its TOC is auto-generated by `private-toc.yml`; **do not hand-edit the TOC block**.

## Conventions

zizmor enforces SHA pinning, explicit `permissions`, `persist-credentials: false`,
and input injection safety. Do not work around findings or suppress them to make CI pass.

Rules that linters cannot catch:

- **Inject inputs via env vars.** Never interpolate `${{ inputs.* }}` directly into a `run:` shell. Pass through an `env:` key and reference the env var in the script. Env var names vary per action — check the existing file.
- **Fork-gating.** Snapshot and some release workflows (`maven-snapshot`, `gradle-snapshot`, `sbt-snapshot`, `sbt-release`, `mend-ci`) take a required `project_name` input and guard the job with `if: github.repository == inputs.project_name`. `maven-release` and `gradle-release` do not have this guard — do not add or remove it without understanding caller impact.
- **`concurrency`.** All workflows declare a `concurrency` group keyed on `github.workflow`/`github.ref`. Use `cancel-in-progress: true` except for release workflows (`sbt-release` uses `false`).
- **`fetch_all_commits` input** maps to `fetch-depth: ${{ inputs.fetch_all_commits == true && '0' || '1' }}`.

## Boundaries

- Do not broaden `permissions` beyond what the workflow needs.
- Do not suppress zizmor or actionlint findings.
- Do not hand-edit the README TOC block.
- Do not copy `private-*.yml` workflows into other repos.

## Releasing this repo

Run the manual `private-release.yml` workflow from the Actions tab.
